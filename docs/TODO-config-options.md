## Рівень 3 — складні

**Зроблено у v3.0.29.** Зачіпає формат файлів, сумісність між версіями або граматику. Ухвалені рішення: scrypt — новий формат `.enc` (2) лише за явного вибору, за замовчуванням формат 1; власні шаблони — дії mask/skip/warn, `default_action` — для записів без дії; порядок — лише для шаблонних типів (звання й ПІБ завжди після них); `preserve_gender: false` — рід маски імені й по батькові псевдовипадковий (закінчення прізвищ, жіночі звання й дієслова стать видають).

- [x] **26. Власні шаблони** — `masking_rules.custom_patterns`
  - Що: Регулярні вирази користувача → детермінована заміна зі збереженням форми (цифри → цифри), нова категорія в mapping.
  - Складність: Unmask уже узагальнений за категоріями. Потрібні: формат опису, захист від «катастрофічних» regex, перетини з вбудованими типами, тести round-trip.
- [x] **27. Альтернативне виведення ключа (scrypt)** — `security.key_derivation`, `security.scrypt_n`, `security.scrypt_r`, `security.scrypt_p`, `security.salt_length`
  - Що: Новий формат `.enc` із заголовком (KDF і параметри); читання старого формату зберегти.
  - Складність: Файли нового формату не прочитають старі версії програми. За замовчуванням лишити PBKDF2 і старий формат. У прикладі стоїть `scrypt` — **значення треба змінити на `pbkdf2`**.
- [x] **28. Маски без ознаки статі** — `masking_rules.preserve_gender`
  - Що: `false` — маска не видає стать: ім'я і по батькові узгоджено іншого/випадкового роду.
  - Складність: Жіночі звання й дієслова в тексті («прибула») лишаються — граматична неузгодженість. Потрібне рішення, що саме приховувати.
- [x] **29. Порядок обробки** — `router_rules.processing_order`, `router_rules.priority_overrides`, `router_rules.default_action`
  - Що: Налаштовуваний порядок типів і дія для «невизначених шаблонів».
  - Складність: Порядок у рушії жорсткий, і від нього залежить коректність (ініціали до ПІБ, дати до номерів). Поняття «невизначений шаблон» з'явиться лише разом із `custom_patterns`.

## Рівень 4 — недоцільні як перемикачі

Вимкнення зламало б розмаскування або не має визначеного змісту. «Реалізація» — лише перевірка значення.

- [ ] **30. Перемикачі, без яких не працює розмаскування** — `masking_rules.consistent_mapping`, `masking_rules.instance_tracking`
  - Що: Приймати лише `true`; `false` — помилка з поясненням.
  - Складність: Без однозначного mapping і нумерації входжень відновити текст неможливо.
- [ ] **31. Перемикачі без визначеної альтернативи** — `masking_rules.context_aware`, `validation.validate_rank_dictionary`, `remask.auto_numbering`, `remask.save_chain`
  - Що: Приймати лише `true`; `false` — помилка з поясненням.
  - Складність: ПІБ і звання розпізнаються лише за контекстом і словником; проходи перемаскування завжди нумеруються (на цьому тримається `--to-version`). При перемаскуванні chain-файл — це і є mapping: без нього розмаскувати нічим, а скласти проходи в один сумісний mapping код не вміє. Якщо знадобиться — окремий дизайн.
